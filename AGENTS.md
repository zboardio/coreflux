# Working with these templates and an AI assistant

Guidance for an assistant (Claude Code, Copilot, Codex, Cursor…) helping someone use or adapt a
template from this repository in their own project. Read it before changing a notebook.

## What is here

- `templates/<name>/` is one self-contained template: solution notebook, simulator notebook,
  `README.md`, `compose/`, `VERIFICATION.md`, `GALLERY.md`. Start from the template's `README.md`:
  topics, quick start, production readiness and an "Adapting this template" section.
- [`templates/README.md`](templates/README.md) holds the layout, the conventions every template
  shares, and the **LoT lessons measured on 2.14.3**.

## Adapting a template

- **Edit the `.lotnb`.** It is a JSON list of cells (`kind` 1 markdown, 2 code); keep it valid JSON
  and one cell per entry. `src/<notebook>.lotnb.md` is a readable copy of the same notebook and
  nothing in this repo renders it back, so in a fork it may drift; that is fine.
- **Deploy order** is the notebook's: Models → Python → Routes → Actions → Rules. `DEFINE` is the
  first line of a code cell.
- **Device and room ids go in the map action only** (`ON START`), never in the mapper. Anything
  unmapped is published under `…/unmapped/…`, not dropped.
- **Keep the UNS shape**: `<root>/<Area>/<Position>/<Leaf>`, every leaf the five-key envelope
  `value`, `timestamp` (observation time, ISO-8601 Z), `datatype`, `status`, `units` (numeric leaves
  only). Replace the example root `acme/site01` with the user's own.
- **Follow every LoT lesson** in `templates/README.md` before writing LoT. They are failures we hit on a
  real broker that look correct to a model: `GET JSON … == EMPTY` never fires, inline division is
  integer division, `//` silently truncates broker-hosted Python, rule priorities 0–99 are
  reserved, `PUBLISH MODEL` and Routes are seen by Rules under an empty user name.
- A green deploy proves little: an action is compiled when it first runs. Run the simulator
  notebook and read the broker log before calling a change done.

## Secrets

- Never commit `.env`, `secret.yaml` or a Zigbee2MQTT data folder (`z2m-data/`): they hold
  credentials and the Zigbee network key. Only `*.example` files are templates.
- Credentials that the broker uses live in its secret store (`KEEP SECRET` / `GET SECRET`), not in a
  notebook, a topic or `.env`.
- Pin `COREFLUX_SECRET_KEY` (generator in `compose/.env.example`) and back it up; unpinned, a
  restore onto other hardware cannot read a single secret.
- Production: anonymous login off, accounts and Rules in place before any client connects.

## Contributing back

Issues are welcome. A pull request carries nothing of your own estate (no real device id, IP
address, host, site or personal name; use `acme/site01/…` and obviously fake ids), keeps the
template's `README.md` and notebooks saying the same thing, and states the broker version you
tested on. `VERIFICATION.md` is regenerated by the maintainers; do not edit it.
